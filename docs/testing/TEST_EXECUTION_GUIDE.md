# SEO Copilot v1.0.0 - 测试执行指南

## 开始测试前的准备

### 1. 验证扩展构建状态
```bash
# 确认版本号
cat manifest.json | grep version

# 运行测试套件
npm test

# 执行生产构建
npm run build

# 验证构建产物
ls -la dist/
```

### 2. 加载扩展到Chrome
1. 打开 `chrome://extensions/`
2. 启用右上角的"开发者模式"
3. 点击"加载已解压的扩展程序"
4. 选择项目的 `dist` 目录
5. 确认扩展图标出现在工具栏

### 3. 准备测试环境
- 打开 Chrome DevTools（F12）并切换到 Console 标签
- 准备好 [TEST_REGRESSION_MATRIX.md](TEST_REGRESSION_MATRIX.md) 文件用于记录结果
- 建议使用独立的 Chrome 配置文件避免其他扩展干扰
- 确保网络连接稳定

## 测试执行流程

### 标准测试步骤（每个网站重复）

#### 步骤 1: 导航到目标网站
```
1. 在地址栏输入URL并回车
2. 等待页面完全加载（观察标签页图标停止旋转）
3. 如果是首页，等待3秒确保动态内容加载
```

#### 步骤 2: 打开控制台监控
```
1. 按 F12 打开 DevTools
2. 切换到 Console 标签
3. 清空之前的日志（右键 > Clear console）
4. 观察是否有页面自身的错误（记录但不计入扩展测试）
```

#### 步骤 3: 启动扫描
```
1. 点击浏览器工具栏的 SEO Copilot 图标
2. 弹出窗口应显示 "Scan Current Page" 按钮
3. 记录弹出窗口打开时间（性能基准）
4. 点击 "Scan Current Page" 按钮
```

#### 步骤 4: 观察扫描过程
```
监控以下内容：
✓ 扫描进度指示器是否出现
✓ 控制台是否有错误信息（红色）
✓ 控制台是否有警告信息（黄色）
✓ 页面是否有视觉异常（闪烁、卡顿）
✓ 扫描是否在合理时间内完成（<5秒为佳）
```

#### 步骤 5: 验证结果
```
检查扫描结果：
1. 总体评分是否显示（0-100分）
2. 六大类别评分是否完整：
   - Basic Info
   - Technical SEO
   - Content Quality
   - Performance
   - Accessibility
   - Structured Data
3. 每个类别是否有具体问题列表
4. "Impact" 标签是否正确（High/Medium/Low）
5. 建议内容是否合理（不要求完美，但应有意义）
```

#### 步骤 6: 记录测试结果
在 [TEST_REGRESSION_MATRIX.md](TEST_REGRESSION_MATRIX.md) 中更新对应行：

```markdown
| # | 网站 | URL | 扫描 | 控制台 | 评分 | Schema | 性能 | 备注 |
| 1 | 示例网站 | https://example.com | ✅ | ✅ | ✅ | ➖ | ⚠️ | 3.2秒完成 |
```

**图例说明**：
- 扫描: ✅成功 / ❌失败
- 控制台: ✅无错误 / ⚠️有警告 / ❌有错误
- 评分: ✅完整 / ⚠️部分 / ❌缺失
- Schema: ✅解析成功 / ➖无Schema / ❌解析失败
- 性能: ✅<2s / ⚠️2-5s / ❌>5s

## 特殊场景测试指南

### 场景 A: 单页应用（SPA）
**特征**: React/Vue/Angular 站点，内容动态加载

**测试要点**：
1. 等待页面完全渲染后再扫描
2. 检查是否能正确读取 `<title>` 和 `<meta>` 标签
3. 确认动态插入的内容是否被扫描到
4. 观察是否有因 Shadow DOM 导致的问题

**预期行为**：
- 应能读取初始渲染后的 DOM 状态
- 评分应基于当前可见内容，不是源代码

### 场景 B: 电商产品页
**特征**: 大量图片、结构化数据、复杂布局

**测试要点**：
1. 检查 Product Schema 是否被正确解析
2. 验证图片 alt 文本检查是否准确
3. 确认价格、评分等结构化信息是否识别
4. 测试大量图片对扫描性能的影响

**预期行为**：
- Structured Data 类别应显示 Product Schema
- 可能有 "Missing alt text" 问题（很常见）
- 扫描时间可能较长（3-5秒可接受）

### 场景 C: 新闻文章页
**特征**: Article Schema、长文本、发布时间

**测试要点**：
1. 检查 Article Schema 是否被识别
2. 验证标题层级（H1-H6）检查
3. 确认内容长度评估是否合理
4. 测试是否能正确识别作者、发布日期元数据

**预期行为**：
- Structured Data 应识别 Article 或 NewsArticle
- Content Quality 应评估文本长度
- 可能提示优化标题层级

### 场景 D: 超大DOM页面
**特征**: Reddit、YouTube 等无限滚动页面

**测试要点**：
1. 在页面顶部扫描（不滚动）
2. 观察扫描时间是否超过10秒
3. 检查是否有内存溢出或崩溃
4. 确认控制台是否有性能警告

**预期行为**：
- 扫描应在10秒内完成（可能较慢）
- 不应导致页面卡死或扩展崩溃
- 可能有 "Too many elements" 类型的性能建议

### 场景 E: 静态HTML站点
**特征**: 传统服务端渲染、简单结构

**测试要点**：
1. 这是最简单的测试场景
2. 应该快速完成（<2秒）
3. 所有类别应都有评分
4. 不应有任何错误

**预期行为**：
- 这是"理想"测试案例
- 如果静态站点失败，说明存在基础问题

## 常见问题排查

### 问题 1: "Scan Current Page" 按钮点击无响应
**可能原因**：
- 扩展注入脚本失败
- 页面CSP阻止脚本执行
- activeTab 权限未授予

**排查步骤**：
```
1. 查看 Console 是否有 "Refused to execute" 错误
2. 检查 chrome://extensions/ 中扩展权限状态
3. 尝试刷新页面后重新点击
4. 查看 Background Service Worker 日志
```

### 问题 2: 扫描进行到一半卡住
**可能原因**：
- 页面DOM结构异常复杂
- 死循环或无限递归
- 内存不足

**排查步骤**：
```
1. 打开 Task Manager (Shift+Esc) 查看内存占用
2. 查看 Console 最后一条日志位置
3. 等待15秒后判定为超时
4. 记录问题并标记为失败案例
```

### 问题 3: 评分显示为 0 或 NaN
**可能原因**：
- 权重计算错误
- 某个类别返回了无效值
- 除零错误

**排查步骤**：
```
1. 查看各类别的独立评分是否正常
2. 检查 Console 是否有计算错误
3. 截图完整的扫描结果
4. 标记为 P0 阻塞问题
```

### 问题 4: Schema 解析失败但页面确实有 Schema
**可能原因**：
- JSON-LD 格式错误被忽略
- Schema 在 iframe 中
- 页面有多个 Schema 导致混淆

**排查步骤**：
```
1. 右键 > 查看网页源代码
2. 搜索 "application/ld+json"
3. 验证 JSON 格式是否正确
4. 如果格式正确但未识别，标记为问题
```

## 测试数据记录模板

### 成功案例示例
```markdown
| 7 | Next.js 官网 | https://nextjs.org | ✅ | ✅ | ✅ | ✅ | ✅ | 1.8s, Organization Schema |
```
**详细记录**：
- 扫描时间: 1.8秒
- 总评分: 87/100
- 控制台: 无错误
- Schema类型: Organization
- 特殊发现: 性能优秀，所有类别评分正常

### 失败案例示例
```markdown
| 18 | Reddit 首页 | https://www.reddit.com | ❌ | ❌ | ❌ | ➖ | ❌ | 注入失败: CSP blocked |
```
**详细记录**：
- 错误信息: "Refused to execute inline script because it violates CSP"
- 失败阶段: 脚本注入
- 控制台错误: 3个红色错误
- 是否可修复: 需要调整注入策略
- 严重程度: P1（影响主流站点）

## 加速测试技巧

### 并行测试
如果有多台设备或多个浏览器窗口：
```
窗口1: 测试静态站点（1-3）
窗口2: 测试 CMS 平台（4-6）
窗口3: 测试 Next.js（7-9）
...
```

### 快速记录
使用简写快速记录，事后补充详情：
```
1. ✅✅✅➖✅ 1.5s
2. ✅⚠️✅✅⚠️ 3.1s, CSP warning
3. ❌❌❌➖❌ inject fail
```

### 批量验证
对于明显成功的案例，可以快速验证：
- 看到评分就算通过
- 详细检查仅针对失败/异常案例
- 重点关注边界场景

## 参考标准

### 上架合格标准
- ✅ **成功率 ≥ 90%** (18/20 或以上)
- ✅ **无 P0 阻塞问题** (不影响核心扫描功能)
- ✅ **静态站点 100% 成功** (基础功能必须稳定)
- ✅ **主流平台 ≥ 80% 成功** (CMS/Next.js/SPA)

### 不合格标准（需修复后重测）
- ❌ 成功率 < 80%
- ❌ 存在导致崩溃的 P0 问题
- ❌ 静态站点失败率 > 0
- ❌ 主流平台成功率 < 60%
