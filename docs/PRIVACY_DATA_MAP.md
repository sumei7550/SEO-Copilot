|JSON-LD|Active page DOM|Schema presence and validity rules|Memory during report only|None|None|

|Per-tab SEO report, score, issues, and scan/error state|Local scanner and Side Panel|Display and restore reports while the panel is open|Side Panel in-memory Map; not long-term history|Score and issue counts/IDs are sent as analytics properties; the full report is not|Mixpanel receives the listed analytics fields|
|Page context for AI Fix|Sent only after an explicit supported title or meta description request|Generate the requested suggestion through the backend and DeepSeek|No raw page-context write found in reviewed backend code; third-party retention not verified|URL, title, meta, H1, current value, issue details, inferred page type/brand and language go to backend and in the AI prompt|DeepSeek; not an entire page-body upload|
|deviceId|Generated by the extension and kept in `chrome.storage.local`|AI request quota and abuse controls|Stored locally; rate-limit counters are held by Upstash|deviceId is sent with an AI Fix request|No sale or advertising use|

|Mixpanel analytics ID and event properties|Mixpanel SDK on the extension and website|Usage and feature analysis|Browser localStorage and Mixpanel service; retention not verified|Extension action data, score and issue counts/IDs, SDK internal-extension-page URL and browser metadata; website page URL/path, locale and referrer|Mixpanel|
|IP address|AI Fix request network connection|Rate limiting and abuse prevention|Hashed-IP and device rate-limit counters in Upstash; hosting/provider logs not verified|Processed by backend and hashed before Upstash keys|Upstash for hashed counters|

The reviewed scanner does not use browsing-history, cookie, password, or form-value APIs and does not scan content from non-active tabs. Its local visible-text calculation can include text nodes displayed inside forms; it returns derived counts rather than the full text. Mixpanel and infrastructure may derive approximate location or other metadata from network requests; their configuration and retention require separate verification.

## Chrome Web Store privacy answers

- Single purpose: Analyze the user-selected active webpage locally for on-page SEO issues and display actionable recommendations.
- Handles website content: Yes, locally and only after explicit user action.
- Handles web browsing activity: The active tab URL is read when the Side Panel opens or the active page changes, before Scan, to identify the page and restore an in-memory report. It is not saved as browsing history; it is sent to the backend and DeepSeek only for an explicitly requested AI Fix.
- Data sold or shared: The reviewed application code does not sell data or use it for ads. It sends usage analytics to Mixpanel and requested AI context to the backend/DeepSeek; review the dashboard's terminology and disclosures before answering its data-sharing questions.
- Data used for advertising: No.
- Data transmitted off-device: Mixpanel events and SDK default page/referrer properties; on explicit AI Fix, necessary page context and deviceId to the backend and provider. Basic SEO scanning stays local.
- Remote code: No.
- Limited Use certification: Developer must verify the actual Chrome Web Store dashboard declaration before release.
