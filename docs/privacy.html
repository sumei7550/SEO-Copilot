SEO Copilot Privacy Policy

Last updated: October 20, 2026

SEO Copilot analyzes the active webpage for on-page SEO issues. Basic SEO scanning runs locally in the browser.

Data processed

When you open the Side Panel, switch tabs, or navigate, SEO Copilot reads the active tab's ID and URL to identify the page and restore any report held in Side Panel memory. This does not read the page body or start a scan.

Only after you click Scan current page and grant site access if requested does the local scanner read the page URL, metadata, headings, image SEO attributes and dimensions, JSON-LD structured data, and visible text needed for word count and text density. The full visible text is not returned in the report.

The scanner does not use form-value, cookie, password, or browser-history APIs and does not scan the body of unrelated tabs. Its local visible-text calculation may include text nodes displayed within forms; only derived counts are returned.

Use, storage, and sharing

  • Basic SEO scanning is processed locally.
  • Only when you request AI Fix, the page URL, title, meta description, H1 text, selected issue details, and related context are sent through the SEO Copilot backend to DeepSeek. The full page body is not sent.
  • A deviceId and installation, Welcome-view, and first-successful-scan timestamps are kept in chrome.storage.local. Reports are held only in Side Panel memory. The backend uses the IP and deviceId for Upstash rate limiting; the reviewed backend code does not store raw page context, but hosting and provider retention require separate confirmation.
  • SEO Copilot uses Mixpanel for usage analytics. Extension events include actions, score and issue counts/IDs, and SDK defaults such as the current internal extension-page URL and browser metadata—not the scanned site's URL in custom event fields. Website analytics includes this site's URL/path and referrer. Mixpanel uses a browser-local identifier.
  • The reviewed application code does not send data to advertising networks or use it for advertising. Mixpanel, DeepSeek, Upstash, and the backend host process data for the purposes above.

Permissions

tabs provides the active tab ID and URL for page identification; sidePanel opens the panel; activeTab provides temporary user-invoked access; scripting injects the packaged scanner when needed; and storage holds the local identifier and activation timestamps. The http://*/* and https://*/* patterns are optional, not all-site access granted at installation: when you click Scan on a site without access, Chrome asks for that site's permission. Fixed host permissions allow the AI backend and Mixpanel endpoints. The extension requests no Chrome browsing-history or cookie permission.

Limited Use

The use of information received from Chrome APIs adheres to the Chrome Web Store User Data Policy, including the Limited Use requirements. Access supports the user-facing local SEO audit, optional AI suggestions requested by the user, and related operational analytics.

Changes

If a future release changes these practices, this policy and the in-product disclosure will be updated before the changed processing begins.
